# Rootware SDK 开发者指南

SDK 位于 `sdk/`，核心库是 `librootware`。它是标准 Rust SDK，不依赖自定义
构建命令；主机（Linux）与 Rootware 目标都用普通 `cargo`：

## 在 Linux 上开发服务逻辑

```sh
cargo new --bin my-service
# 在 my-service/Cargo.toml 中加入：
# librootware = { path = "<repo>/sdk/librootware" }
cargo build
cargo test
```

Linux 下使用 `InMemoryTransport` / `ServiceRegistry` 测试服务逻辑；同一份
代码拿到 Rootware 上运行时只需把传输换成 `SyscallTransport`。

## 编写真正的 Rootware 用户程序

用户程序是静态 ELF64 可执行文件，由内核从 Multiboot2 引导模块加载：

1. 程序 crate 依赖 `librootware = { path = "../../sdk/librootware",
   default-features = false, features = ["crt0"] }`（no_std 模式,
   crt0 提供入口 shim）。
2. `build.rs` 只需两行,复用 SDK 的共享构建逻辑（链接脚本 + 多语言
   源编译 + lib 引用）：
   `include!("../../sdk/build/user-program.rs");`
   `fn main() { rootware_user_build(); }`
3. 实现 `#[no_mangle] extern "C" fn rootware_main() -> i32`。SDK 的 crt0
   负责从 `_start` 调用它，返回后以返回码调用 `SYS_EXIT`；panic 会打印
   `[PANIC]` 并退出，不会拖垮系统。
4. `./build.sh` 自动发现 `user/` 下的每个组件目录，构建为 GRUB 模块并
   自动生成 grub.cfg；内核按固定策略拉起：`echo-service` 固定为 pid 2、
   `ipc-client` 为 pid 1，其余引导模块按 boot 顺序分配最低空闲 pid，
   无需改内核。

可运行的完整示例在 `user/` 下：`hello`（控制台输出）、`echo-service`
（阻塞接收请求并回复）、`ipc-client`（版本握手、能力请求、发送请求、
打印回包，并端到端读写 RKM 驱动）、`mixed-demo`（四语言混合程序）、
`libcrc`（lib 组件）。

## 构建系统

组件 = `user/<目录>/`。构建系统自动发现一切;清单 `program.toml` 可选
（兼容遗留 `rkm.toml`）：

```toml
[program]
name = "mixed-demo"   # 缺省 = 目录名
kind = "program"      # program | service | driver | lib
entry = "rust"        # rust | c:链接主导方;缺省:有 Cargo.toml → rust
version = "0.1.0"     # driver 注册注入

[c]   sources = ["src/*.c"]   includes = ["c/include"]   # 各语言段可选
[cpp] sources = ["cpp/*.cpp"]
[zig] sources = ["zig/*.zig"]

[link]
libs = ["libcrc"]     # 引用 lib 组件(产物 lib<name>.a)
```

**类型（kind）语义**：

| kind | 语义 | 产物 | 进 ISO | 自启 |
|---|---|---|---|---|
| program | 普通用户程序 | 静态 ELF | ✓ | ✓ |
| service | 常驻 IPC 服务 | 静态 ELF | ✓ | ✓ |
| driver | RKM 驱动（注册语义 + name/version 注入） | 静态 ELF | ✓ | ✓ |
| lib | 静态库组件,供其他组件引用 | `.a` | ✗ | ✗ |

**多语言**：C ABI 是跨语言边界。entry = rust 时,把 C/C++/Zig 源放进
`c/`、`cpp/`、`zig/` 约定目录,共享 build.rs 自动编译并链接进最终 ELF
（Rust 通过 `extern "C"` 调用）;entry = c 时由 `sdk/build-program.sh`
主导编译链接,Rust 部分以 staticlib 并入（不加 crt0 feature）。C++ 约束：
`-fno-exceptions -fno-rtti`,不要用 new/delete（无 libstdc++）。

**命令**：

```sh
./build.sh                    # 全流程:构建 + ISO + QEMU 运行
./build.sh build              # 内核 + 全部组件 + ISO
./build.sh program <名字>     # 构建单个组件
./build.sh driver|service|lib <名字>   # 类型化目标(校验 kind)
./build.sh new <kind> <名字>  # 从模板实例化新组件到 user/<名字>
./build.sh iso | run | test | list | clean
```

新增一个程序/服务/驱动/库 = `./build.sh new <kind> <名字>` 一条命令,
或手工把目录拖进 `user/`。

## RKM：Rootware 内核模块（驱动框架）

RKM（Rootware Kernel Module）模块就是一个用户态驱动进程：启动后通过
`SYS_MODULE_REGISTER` 向内核注册 `{name, version, kind}`，内核在注册表
（容量 8）中绑定其 pid 并打印
`[RKM] module '<name>' v<version> (<native|linux>) registered as pid N`；
驱动随后驻留，阻塞在 `SYS_IPC_RECEIVE` 上等请求。任何进程可用
`SYS_MODULE_LIST` 枚举模块；驱动进程退出时其条目转为 `STOPPED`。

注册即授权：成功注册的模块自动获得 `IPC_SEND` 能力，权限表自动补上
"pid 1 ↔ 驱动" 双向规则。请求使用 `message_type::DRIVER_REQUEST`（类型 5，
路由表无此类型的规则，内核按请求接收方直投到驱动自己的 pid）；驱动以
`RESPONSE` 回包。

请求 payload 约定（内核不解释，SDK 与 C shim 共享）：
`payload[0]` = 操作码（`OP_READ`/`OP_WRITE`），`payload[1]` = 数据长度
L ≤ 30，数据在 `payload[2..2+L]`；回复中 `payload[1]` 为状态
（0 成功 / 0xFF 失败）。

### 路径一：原生 Rust 驱动（librootware SDK）

```rust
use librootware::rkm::{self, module_kind};

let descriptor = rkm::register("my-driver", "0.1.0", module_kind::NATIVE)?;
let receiver = descriptor.pid;          // 内核分配的 pid == 自己的接收方 id
loop { /* transport.receive(receiver) → 处理 → transport.reply(...) */ }
```

`rkm::list(&mut buffer)` 返回注册表条目；`Driver` trait 与 `Service`
镜像（`name`/`version`/`kind`/`init`/`handle`/`stop`）。完整示例：
`user/rkm-driver`（计数器设备）。

### 路径二：Linux 兼容 C 驱动（compat/linux shim)

`compat/linux/rkm.h + rkm.c` 是一层薄 C ABI：Linux 驱动逻辑只需实现
`struct rkm_device_operations { probe, read, write }`（语义对齐
file_operations），再用 `RKM_DEVICE(ops)` 生成入口，即成为常驻 RKM
模块。驱动名字/版本由 `program.toml` 清单在构建时注入 —— 清单是唯一来源：

```toml
[program]
name = "zero-driver"
kind = "driver"
entry = "c"
version = "0.1.0"

[c]
sources = ["src/*.c"]
```

`./build.sh driver <名字>` 经 `sdk/build-program.sh` 把 shim 与 C 源一起
编译成静态 ELF 启动模块（复用 `user/linker.ld`）。完整示例：
`user/zero-driver`（移植自 Linux `drivers/char/mem.c` 的 /dev/zero 逻辑）。

**移植边界**：shim 覆盖 IPC 收发/回复、控制台输出、模块注册与枚举；
不覆盖中断、DMA、总线枚举与内核内存分配 —— Rootware 的驱动运行在
用户态，这些设施由内核或未来的总线服务提供。只依赖内存的 Linux 驱动
逻辑（状态机、协议编解码、ops 分发）可以近乎原样移植；与硬件强耦合的
部分需要适配层。

## 测试

```sh
cargo test --workspace   # 主机单元测试（内核逻辑 + SDK + 模拟器）
./run-tests.sh           # 完整稳定性门：主机测试 + QEMU 启动自检 + 用户态端到端
```

`run-tests.sh` 会在 QEMU 中断言：内核自检套件全部 `[SELFTEST] PASS`、
ABI v5 握手成功、echo 往返输出 `ping from client v1.0`、hello 打印、
进程以 0 退出、`rkm-registry` 自检通过、原生与 Linux 兼容驱动各自注册
（两条 `[RKM] module … registered` 日志）、客户端经 `DRIVER_REQUEST`
从 zero-driver 读到 8 个零字节；随后通过串口管道驱动 shell（`help`、
`modules`、`run hello`、`abi`），断言 shell 就绪、命令输出与 `SYS_SPAWN`
生效，最后以 `exit` 让内核走关机路径退出。

## 模板与模拟器

模板目录 `templates/` 是参考骨架,`./build.sh new <kind> <名字>` 按
`kind` 取用:`program`（普通程序）、`service`（常驻服务）、`driver`
（RKM 驱动清单与骨架,见 `driver/program.toml`）、`lib`（静态库组件）。
Linux 模拟器位于 `sdk/simulator`，提供与内核 IPC ABI 相同布局的内存
传输；真实 Rootware 运行时只需实现 `librootware::ipc::Transport` 即可替换。

服务实现 `librootware::service::Service`，由 `ServiceRegistry` 统一注册和
管理生命周期：

```rust
use librootware::service::{EchoService, ServiceRegistry};

let mut services = ServiceRegistry::new();
services.register(Box::new(EchoService::new()))?;
services.start()?;
// services.dispatch("echo", &request)?;
services.stop();
```
