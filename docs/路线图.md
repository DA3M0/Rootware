# Rootware 2.x 路线图

本文档规划 Rootware 2.x 系列的演进:2.0 落地控制台输入与 shell,2.1 系列
优化内核架构(含动态槽位进程管理器),2.2 系列逐步支持并优化交互系统,
文件系统能力(`FS_`)在 2.2 最后一个小版本上线;持续优化贯穿全程,3.x 及
后续方向单列。每个小版本独立可发布、过稳定性门禁。

## 2.x 总览

| 系列 | 主题 | 关键交付 |
|------|------|----------|
| 2.0(已发布) | 交互元年 | 控制台输入链路、shell、ABI v5(v4 废弃,兼容窗口保留) |
| 2.1 | 内核架构优化 | **动态槽位进程管理器**、抢占式调度、堆与栈重构、中断架构、稳定性专项 |
| 2.2 | 交互系统 | shell 增强、coreutils、VGA 多控制台、devfs、**FS_ 上线**(最后一个小版本) |
| 贯穿 2.x | 持续优化 | 零警告政策、门禁波动监控、文档同步、性能基线 |
| 3.x | 后续优化 | SMP、驱动全面化、网络栈、安全加固(不承诺) |

## ABI 策略(贯穿 2.x)

- **当前 ABI: v5;v4 已废弃。** 2.0 起 v4 只通过兼容窗口
  `ABI_COMPAT_MIN (4) .. ABI_VERSION (5)` 保留握手通过能力,目的是让
  2.0 之前构建的存量二进制继续运行;新代码与全部在树组件一律面向 v5。
- v5 是 v4 的**纯超集**:1–10 号 syscall、44 字节 `Message`、32 字节
  `RkmModule`、错误码全部原样保留,仅追加 11 号 `SYS_CONSOLE_READ`。
- 编号只增不改:2.x 新 syscall 从 **12** 起追加(12–14 已由 2.1 进程
  管理器预留);结构体布局冻结不变,新增快照结构同样 `#[repr(C)]` 冻结。
- 废弃节奏:2.x 全程保持 v4 握手可过;3.0 评估移除兼容窗口。

## 2.0(当前版本,已发布)

- 内核控制台输入链路:APIC 时钟 100Hz 轮询串口 → 内核环形缓冲 →
  阻塞式 `SYS_CONSOLE_READ`(11 号),调度器在 shell 等待输入时 hlt 待机。
- SDK `console::read_bytes / read_byte / read_line`(回显、退格、
  CSI 序列吞没)。
- `user/shell`:`rootware> ` 提示符,`help/echo/clear/abi/modules/run/exit`。
- shell 进入稳定性门禁:run-tests.sh 经串口管道自动驱动并断言输出。
- ABI 升 v5,握手改兼容窗口,v4 标记废弃。

## 2.1 系列:内核架构优化

目标:把"能跑"的内核变成"好管"的内核。每个小版本独立合入、过门禁。

### 2.1.0 动态槽位进程管理器(本系列重点)

现状:进程表是编译期固定的 `MAX_PROCESSES = 8` 静态数组(`KSTACKS`
同理),pid 即槽位下标,外部完全不可观测、不可干预,第 9 个进程直接
`QueueFull`。

**设计:槽位动态化 + 进程可管理。**

- 动态槽位:
  - 进程表从静态数组改为**内核堆上动态分配的槽位**:pid 单调递增分配,
    pid → 槽位经空闲链表/动态映射解析;spawn 按需分配新槽位与内核栈页,
    exit 回收槽位、内核栈与地址空间;
  - 进程数上限由可用内存决定,`run` 不再撞 `QueueFull`,`ps` 不再受
    8 行截断;RKM 注册表同步动态化(现为 capacity 8 静态数组);
  - 现有"pid 1/2 引脚 + 权限表"语义保持:引脚 pid 保留低号段,权限表
    与 `CAP_WHITELIST` 改按 pid 段匹配。
- 新 syscall(追加编号,快照结构体冻结布局):
  - `SYS_PROCESS_LIST (12)`:拷出进程表快照(pid、状态、用户/内核、
    等待对象、退出码占位),用户态可枚举;
  - `SYS_KILL (13)`:按 pid 终止进程,回收槽位与 RKM 记录,权限受
    能力约束;
  - `SYS_WAIT (14)`:等待指定 pid 退出并取回退出码,补齐
    spawn→wait→reap 生命周期。
- SDK `process` 模块补齐 `list / kill / wait` 封装。
- shell 集成 `ps`、`kill <pid>`,与现有 `run` 形成完整进程操作闭环。
- `src/audit.rs` 的审计日志经 syscall 暴露(编号顺延,见 2.0 遗留注释)。
- **验收**:门禁新增 procman 用例(`ps` 输出、`run` + `kill` 往返、
  `wait` 取退出码);spawn 数量 > 8 的动态槽位压力用例;引脚 pid
  (client 1 / echo 2)回归不变。

### 2.1.1 调度与内存

- 抢占式调度:APIC 时间片 + 优先级,消除 CPU 密集进程饿死交互进程的
  可能;协作式 `yield`/阻塞语义保持不变。
  验收:构造 CPU 密集进程 + shell 并存,shell 提示符响应不劣化。
- 堆分配器升级(slab/buddy),降低碎片;每进程独立内核栈从静态
  `KSTACKS` 数组改为按槽位动态分配(与 2.1.0 联动)。
  验收:内核堆自检(碎片/回绕)进 selftest。

### 2.1.2 中断与输入架构

- IO APIC 路由:legacy PIC 解禁,串口 RX 从 100Hz 轮询改为真中断,
  输入延迟从 ≤10ms 降到微秒级;`SYS_CONSOLE_READ` 语义不变。
- PS/2 键盘驱动(中断驱动),为 2.2 的交互增强打底。
- 能力撤销与按 pid 细粒度权限(当前 `CAP_WHITELIST` 是硬编码白名单)。
  验收:selftest 覆盖 IO APIC 路由表;键盘输入进内核输入环形缓冲,
  shell 在无串口的启动模式下可用。

### 2.1.3 稳定性专项

- 排查 2.0 发布验证观察到的一次**启动期偶发三重故障**(QEMU 以
  exit 0 复位退出、串口停在 spawn 阶段,复跑两次未复现):怀疑点为
  中断使能时序(`sti; hlt` 窗口)与 GRUB 模块加载时序;门禁改为
  连跑 N 次全绿才算过(见持续优化)。
- 遗留观察项清单随本专项建立:每个偶发问题记录复现条件与结论。

## 2.2 系列:交互系统逐步支持与优化

目标:让 shell 从"演示"变成"日用"。按小版本逐个落地,顺序即依赖顺序。
注:2.2.3 VGA 控制台上线前,QEMU 窗口内的串口虚拟控制台
(View → serial0 / Ctrl-Alt-3)是唯一交互通道。

- **2.2.1 shell 增强**:命令历史(上下键)、Tab 补全(命令名 + 组件名)、
  行内光标移动与插入(当前只有行尾追加 + 退格)。
  验收:门禁驱动历史回放与补全按键,断言不乱码、不吞键。
- **2.2.2 coreutils 第一批**:`cat`、`ls`、`stat` 等 lib 组件形态的
  小工具,复用 libcrc 的 lib 构建路径。
  验收:coreutils 进镜像,门禁断言其输出。
- **2.2.3 图形控制台**:VGA 文本模式/帧缓冲输出 + 多虚拟控制台,
  串口控制台保留为调试通道。
  验收:内核输出与 shell 同时出现在 VGA 屏;控制台切换按键可用。
- **2.2.4 devfs 设备命名**:RKM 模块进入设备树,`/dev/zero` 式命名
  访问,替代裸 pid 直投。
  验收:shell 经设备名而非 pid 读到 zero-driver 数据。
- **2.2.5(本系列最后一个)文件系统上线**:`FS_READ / FS_WRITE` 能力
  正式授予(`capability_kind` 早已预留 2/3,1.x 一直未开放),第一个
  文件系统 ramfs 起步;shell 获得 `ls / cat / cd`,coreutils 接上真实
  存储语义。
  验收:门禁包含"写入→读回→校验"的 ramfs 端到端用例;`FS_` 能力
  授予路径过权限表。

## 贯穿 2.x 的持续优化

不单列小版本,每个提交顺手做、门禁盯着:

- **零警告政策**:kernel/SDK/用户程序 `cargo build` 与测试零 warning,
  出现即修(延续 1.0 的 "clear every build warning" 基线)。
- **门禁波动监控**:`./build.sh test` 由单次通过改为**连跑 N 次全绿**
  才算过(N 起步为 3),抑制偶发故障漏网;失败留存完整串口日志。
- **文档随代码同步**:syscall 表、SDK API、运行说明与代码同提交更新,
  不允许"代码先行、文档欠账"。
- **性能基线**:记录启动耗时、内核堆水位、进程表规模到门禁日志,
  异常漂移即排查。

## 3.x 及后续优化(不承诺)

方向性规划,不排期:

- SMP 多核(Per-CPU 数据、核间中断、调度域)。
- 用户态驱动全面化:RKM 覆盖全部设备类,内核只保留中断路由与 DMA。
- 网络栈(从 virtio-net 起步)。
- 安全加固:栈金丝雀、KASLR 类地址随机化、能力粒度细化。
- 移除 v4 兼容窗口与 legacy PIC 残留路径(3.0 ABI 主版本评估)。
- 图形栈:帧缓冲控制台之上叠 GUI 服务。
- 发布流程:版本号自动同步四 crate、CHANGELOG 自动生成。
